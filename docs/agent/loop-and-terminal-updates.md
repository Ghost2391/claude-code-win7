# 本地循环任务与终端显示

## 推荐：全屏模式

普通模式进一步减少布局抖动：读文件/搜索组的活动详情压成一行，完成后保留该组最后显示过的提示，避免每次完成时删除多行；摘要和 spinner 提示避免自动换行。流式文本暂时隐藏 spinner 时保留两行占位，回合结束后释放。长提示可用 Ctrl+O 查看详细内容。此优化不改变工具执行、权限提示或结果消息，不消除手动展开和窗口缩放导致的高度变化。

普通终端频繁闪烁、上翻时跳到记录顶部时，先用 `CLAUDE_CODE_NO_FLICKER=1 ./claude` 启动一次全屏模式。全屏模式使用备用屏幕与程序内部虚拟滚动，不依赖终端原生滚动历史。使用滚轮、PgUp/PgDn 阅读，Ctrl+End 回到底部；设置 `CLAUDE_CODE_DISABLE_MOUSE=1` 可关闭鼠标捕获，仅使用键盘滚动。

确认合适后执行 `/tui on`，退出并重新启动。程序现会自动读取 `.claude/.tui-mode`（尊重 `CLAUDE_CONFIG_DIR`），不再要求修改 shell 配置。`/tui off` 关闭持久偏好；显式 `CLAUDE_CODE_NO_FLICKER=0` 始终强制普通模式，`=1` 强制全屏。偏好在首次读取时固定，本次会话不会因写入标记而切换整个渲染树。

普通模式默认只按绝对坐标重绘可见视口：不清屏、不清滚动历史，因此不会闪烁，也不会在收缩/展开时跳回会话顶部。流式输出偶尔导致历史区出现一次重复段落（终端无法回删已滚出的行），可用 `CLAUDE_CODE_FULL_CLEAR_ON_RESET=1` 恢复“清屏+清滚动历史”的旧行为。全屏模式不受该选项影响。

本次修复了备用屏幕首次绘制和完整重绘的末行换行：满屏后额外换行会滚掉首行，导致后续增量帧错位。模拟测试覆盖连续窗口变化、无同步刷新优化路径和退出恢复 shell；尚不能证明真实麒麟终端的滚轮事件与虚拟列表高度估计在所有情况下都稳定，需要实机复测。

## `/loop`

- `/loop 5m 检查 CI`：固定间隔，创建一个 recurring Cron 任务，并立即执行一次。
- `/loop 检查 CI`：由模型根据结果选择 1–60 分钟的下一次间隔，使用单次 Cron 任务继续运行。
- `/loop` 或 `/loop 15m`：每轮通过文件读取工具查找项目 `.claude/loop.md`，其次为用户配置目录下的 `loop.md`；没有文件时执行内置维护任务。
- 显式传入任务时不读取默认提示词。默认文件每轮重新读取，因此修改可在下一轮生效。
- 使用 `/cron-list` 查看任务，`/cron-delete <id>` 取消。动态循环每次重新调度会产生新的任务 ID。

动态循环是现有 Cron 工具上的提示词实现，依赖模型执行重调度指令；没有官方专用 ScheduleWakeup 工具的自动兜底或 Escape 取消语义。循环遵循原有权限检查，动态任务保留首次创建时的过期时间，不应逐轮延长。

当前普通任务仍是进程内任务，退出后不会随 `--resume` 自动恢复。需要跨重启的任务应显式使用现有 `durable: true`，其作用域是项目，而不是会话。不能把两种持久化语义混为一谈。

官方行为参考：<https://code.claude.com/docs/en/scheduled-tasks>。

## 智能体面板

普通显示保留最多三条可折叠的空闲队友行。全部空闲 30 秒后收起空闲行；工作中的、正在查看的、有错误的或等待计划批准的队友不会因空闲折叠而隐藏。进入原有智能体选择模式后展开全部行，导航索引与原始列表一致。

该改动针对现有队友树，不合并独立后台 subagent 列表，也不恢复退出后已不存在的队友进程。

## 回归验证

`packages/@ant/ink/src/core/__tests__/log-update-terminal.test.ts` 使用 xterm headless 检查真实 ANSI 输出后的屏幕、光标和滚动历史，覆盖满宽行、中文右边界、128 帧静态重绘与持续增长。它不代替 Windows conhost 的手工验证。

Provider profile 仅撤销本进程覆盖过的环境变量；停用或删除时恢复覆盖前的配置。未启用 profile 时保留 shell 和 settings 注入的 API 配置。

### 主屏重绘与 IDEA 终端

对照上游 `claude-code-best/claude-code` 的 `963e0013184ecc1521289a0fc7d5da4bb6e45356` 后，修复渲染坐标问题：

- 所有视口重绘都预留逻辑光标所在行，通过绝对定位恢复光标，不再追加换行。首次跨越视口和屏外内容变化也不额外推入一行历史。
- 超出窗口的内容块收缩时立即重建可见行映射，避免后续相对光标移动错位。
- 重绘与增量输出使用相同的 emoji 宽度补偿与右边界保护，兼容部分终端较旧的 Unicode 宽度表。

新增测试通过生产用的 diff 优化和 ANSI 序列化路径，在 xterm headless 中验证首次溢出、屏外更新、反复增长/收缩和旧 Unicode 宽度表。修复前分别复现了多滚一行、重复历史、纵向错位和 emoji 后横向错位。

IDEA 内置终端可能使用不同版本的终端内核。这些自动测试不等同于已在麒麟 Linux + IDEA 上验证。更新二进制后，可用长段流式输出、展开/收起工具输出和中英文混合内容复测；聊天历史中的既有重复行不会被主动清除。需记录 IDEA 版本、终端模式、`TERM`、`TERMINAL_EMULATOR` 及 Linux CPU 架构以排查剩余差异。

进一步复现：仅重绘视口时，8 行内容收缩到 6 行再展开，旧滚动历史没有撤销，同一行会逐次重复。此前的方案是在收缩时清屏并清除滚动历史，虽然消除了重复，但每次小幅收缩都会闪屏并把会话拉回顶部。现改为：收缩时直接按绝对坐标重绘新的底部视口，不做任何清屏；之后的回涨在超过收缩前高度之前同样只重绘、不追加，避免把已显示过的行再次滚入历史。代价是滚动历史中可能出现一次重复段落（见上），默认接受。旧 Windows conhost 行为一致；需要旧行为时用 `CLAUDE_CODE_FULL_CLEAR_ON_RESET=1`。新增测试检查整个终端缓冲区，而非只检查最后一屏。
