# 本地循环任务与终端显示

## `/loop`

- `/loop 5m 检查 CI`：固定间隔，创建一个 recurring Cron 任务，并立即执行一次。
- `/loop 检查 CI`：由模型根据结果选择 1–60 分钟的下一次间隔，使用单次 Cron 任务继续运行。
- `/loop` 或 `/loop 15m`：每轮通过文件读取工具查找项目 `.claude/loop.md`，其次为用户配置目录下的 `loop.md`；没有文件时执行内置维护任务。
- 显式传入任务时不读取默认提示词。默认文件每轮重新读取，因此修改可在下一轮生效。
- 使用 `/cron-list` 查看任务，`/cron-delete <id>` 取消。动态循环每次重新调度会产生新的任务 ID。

动态循环是现有 Cron 工具上的提示词实现，依赖模型执行重调度指令；没有官方专用 ScheduleWakeup 工具的自动兜底或 Escape 取消语义。循环遵循原有权限检查，动态任务保留首次创建时的过期时间，不应逐轮延长。

当前普通任务仍是进程内任务，退出后不会随 `--resume` 自动恢复。需要跨重启的任务应显式使用现有 `durable: true`，其作用域是项目，而不是会话。不能把两种持久化语义混为一谈。

官方行为参考：<https://code.claude.com/docs/en/scheduled-tasks>。

## 智能体面板

普通显示保留最多三条可折叠的空闲队友行。全部空闲 30 秒后收起空闲行；工作中的、正在查看的、有错误的或等待计划批准的队友不会因空闲折叠而隐藏。进入原有智能体选择模式后展开全部行，导航索引与原始列表一致。

该改动针对现有队友树，不合并独立后台 subagent 列表，也不恢复退出后已不存在的队友进程。

## 回归验证

`packages/@ant/ink/src/core/__tests__/log-update-terminal.test.ts` 使用 xterm headless 检查真实 ANSI 输出后的屏幕、光标和滚动历史，覆盖满宽行、中文右边界、128 帧静态重绘与持续增长。它不代替 Windows conhost 的手工验证。

Provider profile 仅撤销本进程覆盖过的环境变量；停用或删除时恢复覆盖前的配置。未启用 profile 时保留 shell 和 settings 注入的 API 配置。
